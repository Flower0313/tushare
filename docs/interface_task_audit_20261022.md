## 范围与方法

- 目录共 140 个接口；退役的 `stk_account_old` 已禁用并从可执行目录隐藏，当前可执行接口为 128 个。
- 对可访问接口使用小样本真实预览；有数据时执行两次相同的 UPSERT，同步前后比较目标表行数、第二次新增行数和平台管理的唯一约束状态。批量代码策略只选一个预览得到的代码，避免验收脚本意外扩展至全市场。

## 本轮发现并处理

1. `forecast` 官方要求 `ts_code` 或 `ann_date`，补充 Metadata 的 `any_of` 校验。
2. `stk_account_old` 已不可调用，标记退役并隐藏，不再向用户提供虚假的可执行入口。
3. `stk_mins` 日期时间参数原本按纯日期校验，现支持日期时间格式；真实预览取得 7 行。
4. `stk_mins` 的真实同步随后收到上游 `1次/小时` 限流，已把该接口本地限速设为每 3660 秒一次并迁移到数据库。原验收执行 `ec899d63-2729-489b-bb2d-f6e9176f1020` 最终为上游 `HTTP_429`，机器报告中最初的 `TIMEOUT` 只是轮询超时，不是同步最终状态。额度窗口内不再重试。
5. `report_rc` 多次返回上游 429；[官方文档](https://tushare.pro/document/2?doc_id=292)描述了该接口的积分和日请求额度。当前凭证的实际额度尚未确认，本轮停止重复请求。上游 429 现在不再被请求执行器立即重试，避免浪费额度。
6. 全局与接口级速率门控改为 PostgreSQL 原子预约，API 与 Worker 共享接口级节流；等待发生在事务外，首个请求不会无故等待整段间隔。
7. 浏览器全接口巡检原脚本把虚拟列表中的“全部代码”误当普通选项，改为读取真实代码后通过搜索框选择。该项属于测试脚本修复，不是业务接口故障。

## 仍待真实环境补验

- `stk_mins`：等官方小时窗口恢复后，小样本重新执行两次 UPSERT，核查第二次零新增与表行数不变。
- `report_rc`：确认当前 Token 的积分和日配额后，在允许的额度内补验；不能靠自动重试探测额度。
- 29 个权限受限接口需具备权限的凭证；6 个空样本接口需找到非空的有效日期/代码组合。
- 大范围全市场、高并发、长期调度与生产完整性仍需要独立验收；当前小样本幂等通过不应被表述为这些场景全部通过。
